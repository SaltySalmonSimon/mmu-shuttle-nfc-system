Description / Methods: The Adapter Strategy

Slide 5 of 11
1. Decoupled Architecture (No Lock-In)

The backend accepts standard JSON (cardUid + GPS). USB readers, Raspberry Pis, or phone NFC can be swapped anytime without changing backend code.

2. 5-Second Sliding Debounce Filter

Students linger at readers or double-tap in confusion. An in-memory concurrent cooldown window eliminates accidental duplicate boarding counts.

3. Zero Driver Distraction (Auto-Geofencing)

Drivers cannot safely log stations while driving. Haversine distance automatically maps the bus GPS coordinates to the nearest campus station.

4. Preserves Baseline Fleet Stability

Integrates smart card verification on top of Ka Sheng's platform without altering or destabilizing existing GPS routes, ETAs, or tracking.

Problems Encountered & Ways to Improve

Slide 7 of 11
1. Absence of Physical Machine (Primary Constraint) Hardware Delay

Physical ACR122U readers are pending university procurement and bus installation.

✓ Improvement: Built an automated Node.js edge simulator and prepared mobile NFC fallback to test the entire software pipeline.

2. One-Way Tap In (No Exit Gate) Operational

Students tap when boarding, but do not tap out when exiting.

✓ Improvement: Added a one-touch HUD trip reset for drivers; recommended dual-beam infrared sensors for future upgrades.

3. Campus Cellular Dead Zones Network

Buses may experience momentary signal loss in basements or dense tree coverage.

✓ Improvement: Stateless endpoints allow edge readers to buffer scans locally and flush upon signal restoration.

Recommendation to Others

Slide 10 of 11
💡 Tips for Future Interns
1. Build a Simulator First

Hardware parts often take weeks to arrive. Building a simple software simulator on day one lets you build and test your backend code immediately without waiting.

2. Always Protect Against Double-Taps

In real life, students tap twice or hold cards too long. Always add a simple cooldown timer (like 5 seconds) so nobody gets counted twice.

🏛️ Advice for MMU Management
1. Install Fixed 4G Card Scanners

Mount small, permanent Raspberry Pi card readers with 4G SIM cards inside each bus so the driver doesn't need to manually configure anything.

2. Add Exit Door Counters

Install simple sensors at the back exit door to automatically count students stepping off the bus, keeping the seat count 100% accurate.
